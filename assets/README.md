# 素材の入れかた

絵と音を、ここに置いたファイルに差しかえられます。
**置いていないものは、いままでどおりゲームが自分で描いた絵・合成した音を使います。**
1つずつ差しかえていって大丈夫です。

---

## 0. いちばん大事なこと

素材を **入れたり／消したり／名前を変えたり** したら、かならず一度これを実行してください。

```
python3 build.py
```

ゲームは `assets/list.js` という一覧を見て「どの素材があるか」を判断しています。
その一覧を作り直すのが `build.py` です（ついでに1ファイル版 `starmate.html` も更新されます）。

> **`build.py` は、フォルダ名のまちがいも知らせます。**
> `assets/chara/<キャラid>/` の名前がゲームの知っている id とちがうと、
> **エラーも出ないまま、その子の絵だけ出なくなります**（いちばん見つけにくい事故です）。
> そうなっていたら、`build.py` がこう教えてくれます。
>
> ```
>   ⚠ ゲームが知らないキャラの絵が置かれています。
>       assets/chara/kanadee/  … story.js に「kanadee」というキャラがいません
>     いま story.js が知っているid: aoi chikage daichi hinata kanade …
> ```
>
> `assets/ui/ui_photo_name_<キャラid>.png` も同じように見ます。

> **フォルダは最初から用意してあります。**
> zip を展開すると、下の置き場所が（中身は空のまま）すべて作られています。
> 自分でフォルダを作る必要はありません。あるフォルダに、絵や音を入れるだけです。
>
> ```
> assets/bg/  bgm/  se/  ui/  font/
> assets/chara/<12人ぶん>/
>     full/    ← ふだんの服（制服・冬）の立ち絵。まずはここに入れます
>       uniform_s/ casual/ gym/ club/ pajama/ swim/ yukata/ kimono/
>     bust/    ← ふだんの服の顔画像。まずはここに入れます
>       uniform_s/ casual/ gym/ club/ pajama/ swim/ yukata/ kimono/
>     save/    ← きろく画面の顔
>     face/  outfit/   ← 重ね絵モード専用
> ```
>
> **まずは `full/` と `bust/` の“直下”だけで大丈夫です。**
> 中の服の名前のフォルダは、その服の絵を用意したくなったときに使うもので、
> 空のままでかまいません。`face/` と `outfit/` も**重ね絵モード専用**なので、
> AIで絵を作るなら空のままです。
>
> 足りなくなったら `python3 フォルダを作る.py` でいつでも作りなおせます
> （すでにあるものには手を触れません）。

> **ファイル名は、下の表のとおりに正確につけてください。**
> 名前が1文字でもちがうと、ゲームはそのファイルを見つけられず、
> エラーも出さずに「いままでどおりの絵・音」で動きます。

### 使える拡張子

| 種類 | 拡張子 |
|---|---|
| 絵（立ち絵・背景） | `.png` `.webp` `.jpg` `.jpeg` `.gif` `.svg` |
| 音（BGM・効果音） | `.mp3` `.ogg` `.m4a` `.wav` |

この README では読みやすさのため `.png` `.mp3` で書いていますが、
**上のどれでもかまいません**（例：`klass.webp`、`spring.ogg`）。
立ち絵は透過が必要なので `.png` か `.webp` をおすすめします。

> ただし **同じ名前で拡張子ちがいのファイルを2つ置かないでください。**
> どちらが使われるか決まりません（例：`klass.png` と `klass.jpg` の両方はNG）。

## 1. 立ち絵

> ## ★まず読んでください：立ち絵は「1枚」で足ります
>
> このゲームは、**立ち絵の表情を動かしません。**
> 表情の変化は、メッセージ枠の**左どなりに置く顔画像**で見せます。
>
> ```
>            ┌──────────┐
>            │  立ち絵   │   ← ふつうの顔のまま。1枚だけ
>            │  (1枚)    │
>   ┌─────┐  │           │
>   │     │  └──────────┘
>   │ 顔  │ ┌─────────────────────────┐
>   │     │ │ 名前                     │
>   │画像 │ │ 「セリフ……」            │
>   └─────┘ └─────────────────────────┘
>     ↑ここで表情が変わる（枠線なし。頭から鎖骨あたりまで）
> ```
>
> なので、1人ぶんに必要な絵はこれだけです。
>
> | | 枚数 | 大きさ |
> |---|---|---|
> | 立ち絵 | **1枚** | 1024×1536（縦長） |
> | 顔画像 | **5枚** | 768×1024 くらいの**縦長**（3:4） |
>
> AIの画像生成が出せるサイズが、そのまま使えます。
> くわしくは下の「3. 顔画像」を読んでください。
> （`assets/config.js` の `FACE_WINDOW.on` を `false` にすると、
> 　昔どおり立ち絵の表情が変わる方式にもできます）

---

立ち絵の入れかたは **2通り**あります。どちらでもかまいませんし、
子によって使い分けても大丈夫です。

| | A：1枚絵モード | B：重ね絵モード |
|---|---|---|
| 置きかた | `full/` に完成した立ち絵をそのまま | `base` `outfit` `face` を別々に |
| 最小の枚数 | **1人5枚**（表情ぶん） | 1人5枚（体1＋表情4） |
| 服を増やすと | 服の数 × 表情の数 だけ増える | 服1枚ぶんだけ増える |
| 絵を用意する難しさ | **かんたん**。ふつうに1枚描く／生成するだけ | むずかしい。体・服・顔がぴたりと重なる必要がある |
| AIの画像生成 | **向いている** | 位置合わせができず、ほぼ無理 |

**AIに描いてもらうなら、迷わず A（1枚絵モード）です。**
両方置いた場合は、1枚絵モードが優先されます。

---

### A：1枚絵モード（おすすめ）

`assets/chara/<名前>/full/` に、**そのまま完成している立ち絵**を置くだけです。

```
assets/chara/kanade/full/
    normal.png   happy.png   blush.png   sad.png   worry.png     ← まずはこの5枚
assets/chara/kanade/full/casual/                                  ← 私服（あとから足せます）
    normal.png   happy.png   blush.png   sad.png   worry.png
```

- **`full/` の直下**が「ふだんの服」（制服・冬のつもり）です。まずはここに5枚だけでOK。
- **服の名前のフォルダに入れると、服が増やせます**（フォルダは用意してあります）。
  例：`full/swim/normal.png` を置くと、海やプールのときだけ水着になります。
  フォルダ名は衣装の名前（「2. 服（衣装）のファイル名」の表）です。
- その場面の服が無ければ `full/` の直下へ、その表情が無ければ `normal` へ自動で落ちます。
  **`full/normal.png` の1枚だけでも動きます。**

大きさは **1024 × 1536 以上**（縦長・透過PNG）。詳しくは下の「大きさ」を読んでください。

---

### B：重ね絵モード

**1枚の完成絵ではなく、4枚を重ねて1つの立ち絵にします。**

| 重ねる順 | ファイル | 中身 |
|---|---|---|
| ① いちばん下 | `base.png` | 体・素肌・後ろ髪。**服も顔も描かない** |
| ② | `outfit/○○.png` | 服。①の上に重なる |
| ③ | `face/○○.png` | 表情（眉・目・口・頬）。②の上に重なる |
| ④ いちばん上 | `front.png` | 前髪など、服より前に来るもの（**なくてもOK**） |

こうすると、表情13種類 × 衣装15種類 = 195通りが、**1人あたり最大30枚**で足ります。
枚数はとても少なくて済みますが、**4枚が1ピクセルもずれずに重なる**必要があるので、
手描きでレイヤーを分けて描く場合か、3Dモデルから書き出す場合に向いています。

### 大きさ（A・B共通）

理想は **1800 × 2820 ピクセル**（透過PNG）です。
ただし **AIの画像生成は 1024×1536 までしか出せません**。その場合は
**1024×1536 で作って、あとから2倍に引きのばす**のがおすすめです（下の「AIで絵を作るときは」）。
重ね絵モードのときは、4枚とも同じ大きさ・同じ位置で描いてください。

> **なぜこの大きさ？**
> ゲームの内部座標は 1200×675 ですが、画面に合わせて拡大して表示します。
> 文字やSVGの絵は拡大してもぼやけません（そのつど描き直されるため）が、
> **写真やイラストのファイルは、元の大きさを超えて拡大するとぼやけます。**
> 立ち絵は画面の高さの約93%に表示されるので、必要な実ピクセル数はこうなります。
>
> | 遊ぶ画面 | 立ち絵に必要な大きさ |
> |---|---|
> | 1200×675（等倍） | 400 × 627 |
> | フルHD 1920×1080 | 640 × 1003 |
> | WQHD 2560×1440 | 854 × 1338 |
> | 4K 3840×2160 | 1280 × 2006 |
> | 高DPIノート（実質2.4倍） | 960 × 1505 |
>
> 1024×1536 なら WQHD（2560×1440）まではきれいです。4Kだけが少し足りません。
> **描き直しがきかないので、大きめに作っておくのが安全です**
> （小さくするのは簡単ですが、大きくはできません）。

### AIで絵を作るときは

ChatGPTなどの画像生成が出せるのは、いまのところ次の3種類だけです。

| 向き | 大きさ | 使いみち |
|---|---|---|
| 縦長 | **1024 × 1536** | 立ち絵 |
| 横長 | **1536 × 1024** | 背景（16:9に切ってから使います） |
| 正方形 | 1024 × 1024 | ─ |

**手順**

1. **1枚絵モード（A）で作る。** 重ね絵モードはAIには向きません。
2. まず1人ぶん、**表情ちがいを1枚の紙にまとめて**出してもらう。
   「同じキャラクターの表情を6つ、2行×3列に並べた表情シート」と頼むと、
   **1回の生成で作られるので絵柄が確実にそろいます**。
   1枚ずつ何度も生成すると、顔や服がだんだん変わっていきます。
3. 出てきた画像を切り分けて、`normal` `happy` `blush` `sad` `worry` の名前を付ける。
4. **背景を透明にする。** 「背景を透過して」と頼むか、`rembg` や remove.bg などを使います。
5. **2倍に引きのばす。** アニメ調の絵は `waifu2x` や `Real-ESRGAN` でほぼ劣化なく2倍にできます。
   1024×1536 → **2048×3072** になり、4Kでもきれいになります。
6. `assets/chara/<名前>/full/` に入れて `python3 build.py`。

**背景も同じです。** 1536×1024 で出して、16:9（1536×864）に切り、2倍にして 3072×1728 にします。
`assets/chara/_template/` に、目安の線を入れたPNGを入れてあります。
これを下敷きにすると位置がそろいます（テンプレートはゲームには読みこまれません）。

- 絵の**下端**が画面の下端に合うように配置されます
- 青い四角は、**立ち絵から顔だけを切り取るときの範囲**です。顔をこの中に収めてください
  （「くわしく」画面の顔アイコンと、`save/` に絵を置いていないときのきろく画面で使われます）
- 位置がずれる子がいたら `assets/config.js` の `ART_HEAD` で、その子だけ調整できます

## 3. 顔画像（表情はここで変わります）

メッセージ枠の**左どなり**に置かれます。

```
assets/chara/kanade/bust/
    normal.png   happy.png   blush.png   sad.png   worry.png
```

### ★ いまは「白いポラロイド枠ごと、絵に描きこむ」作りです

`assets/config.js` の `VN_UI.photoInImage` が `true` になっています。
このときは、**この絵のほうに白い枠と、頭のはみ出しまで描きこんで**ください。
ゲームは切りぬきをせず、**その絵をそのまま置く**だけです。
**傾きだけはゲーム側**でかけます（`VN_UI.photoTilt`）。絵はまっすぐ描いてください。

| | |
|---|---|
| 大きさ | 横 **1000 × 縦 1300** くらい（もっと大きくてもかまいません） |
| 形式 | **透過PNG**。写真のまわりは透明に |
| 中身 | 白いポラロイドの枠（**まっすぐ**） ／ 窓の中の写真 ／ 枠から出る髪 |

- **★ 表情ちがいの絵は、キャンバスの大きさも枠の位置もまったく同じに。**
  ずれていると、表情が変わるたびに写真がガタッと動いて見えます
- **絵のいちばん下＝写真のいちばん下**にしてください
- 影は描いても描かなくてもOK（`VN_UI.photoShadow` を `false` にすると消せます）
- 大きさ・位置の調整は `VN_UI` の `photoW` / `photoX` / `photoBottom` / `photoClear`
  （くわしくは `assets/ui/README.md`）

### 枠を描きこまないとき（`photoInImage: false`）

**頭のてっぺんから鎖骨あたりまで**の絵を用意してください。
枠はゲームのほうで付けます（`assets/ui/ui_photo_frame.png` が必要）。

- **縦長（3:4）がおすすめ**。768×1024 くらい。**背景は透過（png / webp）**にしてください
- 上下左右にすき間を作らず、**絵いっぱいに顔と肩**を入れてください
  （画面では枠の中に収まるように、縦横の比を保ったまま縮められます）
- ファイル名は立ち絵の表情と同じ5つ。`normal` があれば、足りない表情はそれで代わります
- **1枚も置かなくても動きます。** そのときはSVGで「頭から鎖骨まで」を描きます
  （立ち絵の画像だけある子は、その顔のあたりを切り取って使います）

### 服ごとに変えたいとき

立ち絵と同じで、**服の名前のフォルダ**に入れればそれが使われます
（フォルダは最初から用意してあります）。

```
assets/chara/kanade/bust/            ← ふだん着ているもの（制服・冬）
    normal.png   happy.png   …
assets/chara/kanade/bust/casual/     ← 私服。公園・カフェ・街などで使われます
    normal.png   happy.png   …
assets/chara/kanade/bust/yukata/     ← 夏祭りの浴衣
    normal.png
```

**急ぐ必要はありません。** `bust/` の直下に5枚あれば、どの場面でもその絵が出ます。
服のフォルダは、余裕ができてから1つずつ足していけば大丈夫です。

服の名前と、どの場面で使われるかは、
`assets/config.js` の `OUTFIT_RULE`（このファイルの「2. 服」と同じ表）で決まります。

探す順番は **① その場面の服 → ② `bust/` の直下 → ③ 代わりの服** です。
その服のフォルダに `happy.png` が無ければ、**同じ服の `normal.png`** が使われます
（服が急に変わってしまわないように、表情より服を優先します）。

### AIで作るとき

顔画像は**縦長（3:4）**なので、画像生成の「縦長」がそのまま使えます。
1024×1536 で作って、下を切って 768×1024 にしてもかまいません。

1. 立ち絵を1枚（1024×1536）作る
2. その立ち絵を見せて「**この子の頭から鎖骨までを、背景なしの縦長で。表情は◯◯**」と頼む
3. 5つの表情ぶん作って `bust/` に入れる
4. 私服ぶんが要るなら、同じ手順で `bust/casual/` に入れる

顔と肩だけなら**全身が写らないので、絵柄がずれにくい**のも利点です。
立ち絵と顔画像で多少タッチが違っても、別々の場所に出るので気になりません。

### 顔画像を使わない場合

`assets/config.js` の `FACE_WINDOW` を直します。

```js
const FACE_WINDOW = {
  on: false,          /* false ＝ 顔画像を出さず、昔どおり立ち絵の表情が変わる */
  standing: "normal", /* 顔画像を使うとき、立ち絵をどの表情で固定するか */
  width:   0.185,     /* 顔画像の横はば（画面の横はばに対する割合） */
  widthMb: 0.165,     /* スマホのときの横はば */
  height:  1.45       /* 顔画像の高さ（メッセージ枠の高さの何倍か） */
};
```

`on: false` にすると顔画像は出ず、メッセージ枠が画面いっぱいに広がります。
そのかわり、立ち絵の表情ぶん（`full/happy.png` など）が必要になります。

## 3.5 きろく画面の顔画像

きろく（セーブ）画面のカードには、**いちばん好感度の高い子の顔**が出ます。
その絵をここに置きます。

```
assets/chara/kanade/save/
    friend.png   crush.png   love.png
```

| ファイル名 | いつ出るか |
|---|---|
| `friend.png` | 「友達」になったとき |
| `crush.png` | 「気になる人」になったとき |
| `love.png` | 「好き」になったとき |

- **正方形（1:1）**がおすすめ。**512×512** くらい。**背景は透過（png / webp）**
  （カードでは**丸く切り抜いて**出すので、顔をまんなかに置いてください）
- 「普通」のあいだは顔を出しません（カードは空欄になります）
- その間柄の絵が無ければ、**ひとつ下の間柄の絵**が使われます。
  `friend.png` の1枚だけでも動きます
- **1枚も置かなくても動きます。** そのときは立ち絵の顔のあたりを切り取って出します

顔を出しはじめる間柄を変えたいときは `assets/config.js` の `SAVE_FACE` を直します。

```js
const SAVE_FACE = {
  tiers:["friend","crush","love"],
  min:"friend"      /* "crush" にすると「気になる人」以上でだけ顔が出ます */
};
```

## 3.55 書体（フォント）

|---|---|

| おまけ | `extra` |
| オプション | `option` |

### 置き場所の調整（`assets/config.js` の `UI_RULE`）

数字はぜんぶ「割合」です。実寸の px ではありません。

| | 意味 |
|---|---|
| `menuAlign` | `"left"` 左寄せ ／ `"center"` まんなか ／ `"right"` 右寄せ |
| `menuX` | 画面のはしからの余白（横はばに対する割合） |
| `menuY` | 上下の位置。0＝まんなか。プラスで下へ |
| `logoX` | ロゴだけ左右にずらす（マイナスで左へ） |
| `menuGap` / `btnGap` | ロゴとボタンのすき間 ／ ボタンどうしのすき間 |
| `logoW` / `btnW` | ロゴとボタンの横はば（`〜Mb` はスマホのとき） |
| `btnIconX` / `btnIconH` | ボタンの中の、アイコンの左右位置と高さ |
| `btnLabelX` / `btnLabelY` / `btnLabelH` | 日本語の文字の左右・上下位置と高さ |
| `btnEnY` / `btnEnH` | 英語の小さい文字の上下位置と高さ |

位置は**その部品の中心**です（`btnIconX: 0.105` なら、土台の左から10.5%のところが
アイコンの中心）。高さだけ決めれば、よこはばは絵の形なりに伸びます。

## 4.5 イベントスチル（1枚絵）

大事な場面で、**画面いっぱいに出るイラスト**です。1人につき **30枚**の枠があります。

```
assets/chara/hinata/cg/01.png        1番のスチル
assets/chara/hinata/cg/01_a.png      1番の差分（表情ちがいなど）
assets/chara/hinata/cg/01_smile.png  差分の名前は自由
assets/chara/hinata/cg/02.png        2番
      …
assets/chara/hinata/cg/30.png        30番

assets/cg/01.png                     みんなのスチル（入学式・卒業式など）
```

| | |
|---|---|
| 大きさ | **2400 × 1350**（背景と同じ 16:9）。もっと大きくてもかまいません |
| 形式 | `.png` `.webp` `.jpg`。**透過は要りません**（画面いっぱいに出るので） |
| 枚数 | 1人 **1〜30**。**差分は、この30枚に数えません** |

### 名前の決まり

- **2桁のゼロづめ**（`01.png`）をおすすめします。
  `1.png` でも動きますが、フォルダの中で 1, 10, 11, 2, 3 … と並んでしまいます
- 差分は **「_」のあとに名前**（`01_a.png` `01_smile.png` `01_night.png`）。
  ゲームからは `vnStill("hinata", 1, "smile")` のように呼びます。
  **その差分が無いときは、差分なしの絵に落ちます**
- **★ 番号は、いちど決めたら変えないでください。**
  イベントIDと同じで、番号が「見た記録」（おまけのスチル）の目じるしです

### 題名

`story/cg.js` に書くと、おまけの「スチル」で絵の下に出ます。書かなくても動きます
（そのときは「スチル 07」のように番号で出ます）。

```js
const CG_TITLES = {
  hinata: {
    1: "はじめての登校",
    2: { t:"屋上のふたり", d:{ a:"照れ顔", b:"泣き顔" } }
  }
};
```

### おまけの「スチル」に並ぶ顔ぶれ

おまけ（🎁）の「🎞 スチル」には、**男女ぜんぶの攻略対象**が並びます。
いま選んでいる主人公の攻略対象が先、そのあとにもう片方、最後に「みんな・その他」です。
スチルを1枚も置いていない子は、見出しごと出ません。

おまけは「集めたものを見る場所」なので、どちらの主人公で遊んだぶんも、
ここに残ります。**もう片方のキャストがいることを、まだ見せたくないとき**は
`assets/config.js` の `GAME_RULE.galleryAll` を `false` にすると、
いま選んでいる主人公の攻略対象だけになります。

> **男性キャラのスチルが出ないとき**
> ・`assets/chara/<キャラid>/cg/` に入っていますか（`ryu` `daichi` など、
>   `story/<id>.js` と同じ id のフォルダです。`python3 build.py` が
>   知らない名前のフォルダを見つけると、そのとき知らせます）
> ・ファイル名は `01.png` のように **2桁のゼロづめ**ですか
> ・`python3 build.py` を実行しましたか（`assets/list.js` が作り直されます）
> ・`GAME_RULE.galleryAll` を `false` にしていませんか

### ★ スマホでは、上下が切られます

スマホを横にすると画面は **16:9 より横長**になります（iPhone 12 mini で約2.17:1）。
ふだんの設定（`CG_RULE.fit: "cover"`）では**上下がそれぞれ1割ほど切られる**ので、
**顔などの大事なものは、まん中に寄せて**ください。

切りたくないときは `assets/config.js` の `CG_RULE` で変えられます。

| 設定 | はたらき |
|---|---|
| `fit: "cover"` | 画面いっぱい（上下が切られる）。ふだんはこちら |
| `fit: "contain"` | 絵ぜんぶを出す（上下に帯が出る） |
| `focusY` | `cover` のとき、たてのどこを中心に切るか（0＝上／0.5＝まん中／1＝下） |
| `charOff` | スチルの間、立ち絵を隠すか（ふだんは隠します） |
| `faceOff` | スチルの間、メッセージ枠の顔を隠すか（ふだんは隠します） |
| `slots` | 1人あたりの枠の数（ふだんは30） |

### ★ 1ファイル版（starmate.html）には、ふだん入りません

スチルは全画面の絵なので、200枚もあると `starmate.html` が数十〜数百MBになり、
開くのに時間がかかってしまいます。そのため **`python3 build.py` では入れません**。

- **フォルダ版・サーバー版（GitHub Pages など）は、いつでもスチルが出ます**
- 入れていない1ファイル版でも、ゲームはちゃんと動きます。
  スチルの場面は「絵が出ないまま、文章だけ進む」形になります
- ぜんぶ入りの1ファイル版が要るときは **`python3 build.py --cg`** で作ります

> 容量を減らすなら **`.webp`（品質80くらい）**がおすすめです。
> 同じ見た目で、`.png` の 1/5 〜 1/10 になります。

## 5. BGM（8ファイル）

```
assets/bgm/spring.mp3   assets/bgm/summer.mp3   …

**自動でくり返し再生**されます。曲の終わりと始まりがつながるように作ると自然です。

| ファイル名 | 曲 | 流れる時期 | いまの合成音のテンポ |
|---|---|---|---|
| `spring` | 春 | 3〜5月（授業のある日） | 108 BPM |
| `summer` | 夏 | 6〜8月（授業のある日） | 126 BPM |
| `autumn` | 秋 | 9〜11月（授業のある日） | 88 BPM |
| `winter` | 冬 | 12〜2月（授業のある日） | 74 BPM |
| `vspring` | 春休み | 3月19日〜4月上旬 | 116 BPM |
| `vsummer` | 夏休み | 7月21日〜8月末 | 138 BPM |
| `vwinter` | 冬休み | 12月25日〜1月上旬 | 82 BPM |
| `title` | タイトル | タイトル画面 | （置かないと `spring` が鳴ります） |

> **音が鳴りだすタイミングについて**
> ブラウザには「利用者がまだ一度も触っていないページでは音を鳴らさない」という
> 決まりがあります（自動再生の制限。ブラウザ側の仕様なので消せません）。
> ゲームは、読みこんだ直後にいちど鳴らしてみて、止められた場合は
> **画面のどこかを最初にクリック／タップ／キー入力した瞬間**に鳴らしなおします。
> それまでのあいだ、タイトルに「🔇 画面をクリック（タップ）すると音が鳴ります」と
> 小さく出ます。**BGMが鳴らないときは、まずこれを疑ってください**
> （ファイル名の間違いではないことがあります）。
- 1曲だけ置いてもかまいません。置いていない季節は、いままでどおりの合成音が鳴ります。

| ファイル名 | 音のイメージ | いつ鳴るか | 長さの目安 |
|---|---|---|---|
| `click` | 軽いカチッ | ボタン・カーソル移動・タブの切りかえ | 〜0.1秒 |
| `ok` | 決定音 | 「実行」「反映」など、話を進めるボタン | 〜0.2秒 |
| `cancel` | 下がる音 | 「もどる」「やめる」「閉じる」 | 〜0.2秒 |
| `page` | ページをめくる音 | 選択肢を選んだ直後・デート先へ移動 | 〜0.1秒 |
| `pinpon` | ピンポン（正解音） | **成功**スタンプ | 〜0.5秒 |
| `title` | 称号の獲得音（きらーん／小さなファンファーレ） | **新しい称号を手に入れたとき** | 〜1秒 |
| `pinpon2` | ピンポンピンポン | **大成功**スタンプ | 〜0.8秒 |
| `bubu` | ブブー（不正解音） | **失敗**スタンプ | 〜0.7秒 |
| `heart` | きらきら・ときめき | 好感度が大きく上がったとき／デートが「最高」 | 〜0.5秒 |
| `great` | 歓声・ファンファーレ | 体育祭のリレーで勝ったとき | 〜1秒 |
| `bad` | 落胆 | 体育祭のリレーで負けたとき | 〜0.5秒 |
| `good` | 小さな成功音 | 予備（いまは鳴りません） | 〜0.3秒 |

- 置いていない音は、いままでどおりその場で合成した音が鳴ります。
- `click` は連打されるので、**短く・音量控えめ**にすると耳が疲れません。
- **`title.mp3` を置かないうちは、`pinpon` が代わりに鳴ります。**
  置いたとたんに、称号のときだけその音に切りかわります。

## 7. 音量

- プレイヤーは**オプション画面**でBGMと効果音の音量を変えられます。
- 素材ファイル側の初期音量は `assets/config.js` の `AUDIO_RULE` にあります。

```js
const AUDIO_RULE = {
  bgmVolume:0.8,   /* BGMの初期音量 */
  seVolume:0.8     /* 効果音の初期音量 */
};
```

## 8. 気をつけること

- **ファイル名は小文字の半角英数字**にしてください（日本語のファイル名は使えません）
- 立ち絵は**透過**が必要です（`.png` か `.webp`）。背景を白く塗ってしまうと、下の層が隠れます
- **大きめに作っておくこと。** 小さくするのは簡単ですが、あとから大きくはできません。
  ファイルが重いときは `.webp`（画質そのままで半分以下になります）がおすすめです
- 素材を全部そろえると1ファイル版がかなり重くなります。人に渡すときは、
  **フォルダごと渡す**ほうが軽くて快適なこともあります（`build.py` が大きさを教えてくれます）
- `assets/list.js` は自動で作られるファイルです。手で直さないでください
- 名前をまちがえても**エラーは出ません**。差しかわらないときは、
  まず `python3 build.py` を実行し、それでもだめならファイル名を見直してください
